[2026-04-21] | Many create/delete cycles against Buffer in a short window triggers rate limit: "Too many requests from this client. [2026-04-21] | Buffer rate limit window is **24 HOURS**, not minutes | Verified via introspection: `extensions.code: "RATE_LIMIT_EXCEEDED", window: "24h"`. Earlier lesson said "5-15 min" -- wrong. Once triggered, Buffer is locked for a full day. Operational rules: (1) before any pipeline run, `schedule-buffer.js` now does a `preflightRateLimit()` probe -- if locked, it aborts before uploading graphics to Drive so we don't waste quota. (2) during debug/testing cycles, minimize create/delete loops. (3) if you hit the limit, Buffer UI still works manually -- fall back to promoting drafts by hand until 24h passes. (4) 30-120s retry backoff in the script is useful for transient throttles within the window but will NOT clear a full 24h rate limit.
